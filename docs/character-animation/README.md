# 원본 캐릭터 유지 + 모든 동작의 크기 고정

2026-09-13. 사용자가 다시 첨부한 `police.png`, `robber.png`를 기준으로
경찰 10개(기본, 달리기 8, 체포), 도둑 11개(기본, 달리기 8, 항복, 탈옥)를
다시 합성했다. 이전에 생성했던 몸체는 사용하지 않는다. 실제 앱 에셋은
`polrob.Client/Resources/Raw/char_*.png`에 적용했다.

## 고정 규격

| 항목 | 값 |
| --- | --- |
| 전체 PNG 캔버스 | 1088×1088 RGBA |
| 공통 머리·몸체 레이어의 최대 너비 | 512px |
| 공통 몸체 중심점 | (544, 544) |
| 게임의 몸체 너비 | 플레이어 지름 × 0.86 |
| 현재 충돌 지름 50일 때 몸체 너비 | 43 월드 단위 |
| 달리기 프레임 간격 | 기존과 같은 100ms |

역할별로 첨부 원본에서 분리한 하나의 머리·몸체 레이어를 모든 동작에 반복 사용한다.
도둑의 목 띠와 어깨를 포함한 원본의 색과 선을 다시 그리지 않는다.
달리기는 원본의 왼팔·오른팔을 각각 분리해 어깨를 기준으로 최대 6도 회전하고,
팔 길이를 반대 위상으로 ±10% 조절한다. 6px의 숨은 겹침으로 어깨 틈을 막고,
손끝은 별도 경계로 잘라 몸통 조각이 팔에 붙어서 움직이지 않도록 했다. 원본에서
손끝과 몸통을 이어 주던 몇 픽셀의 검은 외곽선은 움직일 때 갈고리처럼 튀어나오므로,
따뜻한 색의 손 외곽은 유지하고 그 숨은 연결 픽셀만 점진적으로 제거했다.
몸체는 이동·회전·크기 변경을 하지 않는다. 특수 동작에서도 같은 몸체를 사용한다.
체포 포즈의 팔·손·소품은 보호한 머리·목 아래만 가리고, 탈옥 포즈는 첨부 원본의
자연스러운 어깨 겹침을 살리기 위해 얼굴만 앞 레이어로 보호한다. 도둑의 눈은 원본과
같은 투명 구멍이다. 원본 내부의 253/254 알파도 유지해 반복 합성으로 색이나
투명도가 변하지 않도록 했다.

기본 이미지의 손 뒤에 가려져 있던 좁은 옆구리는 첨부한 체포/항복 포즈에서
둥근 외곽 위치만 측정해 복원했다. 색과 질감은 두 캐릭터 모두 기본 원본에서만
가져온다. 경찰은 원본 옆구리의 외곽색·채움색을 세로 방향으로 부드럽게 이어 붙이고,
도둑은 원본의 40px 안쪽 질감을 새 외곽까지 연속적으로 변형한다. 위·아래 구간에서
점진적으로 원래 외곽으로 돌아오게 하여 갑자기
넓어지거나 좁아지는 단차와 반투명 조각을 없앴다. 보완 몸통을 뒤에, 움직이는 팔을
앞에 두고 중앙의 원본 머리·몸통을 다시 복원하므로 접합선이 팔 위로 드러나지 않는다.

경찰 체포 동작은 얼굴만 고정 보호해 예전의 파란 목 장식처럼 보이던 중복 몸통을
없앴다. 경찰 달리기 6~8의 모자–팔 경계는 수평 절단 대신 원본 곡선을 따라가며,
손–검은 벨트 접점의 외곽도 연속 곡선으로 합성한다. 도둑의 회색 머리띠와 양쪽 끝은
모든 달리기·항복·탈옥 프레임에 원본 픽셀을 다시 씌우되, 아래 회색 몸통과는 별도
레이어로 유지한다. 탈옥 동작에서는 마스크의 손목과 열쇠 이빨 누락 구간을 보완하고
원본 알파로 다시 잘라 머리·몸통·팔·손·열쇠·자물쇠 사이의 작은 틈을 막았다.

팔과 소품에 필요한 여백을 모든 PNG에 동일하게 확보했다. 탈옥 포즈의 높은
어깨와 자물쇠 간격을 축소하지 않고 담기 위해 캔버스만 1088px로 넓혔다. 따라서 전체 이미지로
애니메이션을 만들 때에도 크기·중심점 보정이 필요 없다. 게임에서는 모든 상태가
하나의 `PlayerSpriteProfile(512, 544, 544)`을 사용한다. 투명 여백을 건너뛰는
렌더링 최적화는 배율에 영향을 주지 않는다.

탈옥 에셋 이름은 사용자가 변경한 `char_robber_prison_break.png`를 유지하고
로딩 코드와 같은 이름을 사용한다. 이번 작업에서는 사용자가 수정한 클라이언트와
서버의 플레이어 반지름 25 설정을 변경하지 않았다.

- [인터랙티브 미리보기](../character-run-edges/preview.html): 현재 앱 에셋 21개를
  직접 로드하며, 전체 동작/달리기 선택·일시 정지·프레임 이동·배경·중심 가이드를 제공한다.
- [경찰 원본 + 전체 프레임](result/police-all-states.png), [도둑 원본 + 전체 프레임](result/robber-all-states.png).
  각 시트 첫 칸은 첨부 원본을 같은 배율과 중심점에 배치한 비교 이미지다.
- [검사 기록](result/audit.json): 캔버스, 몸체 규격, 보호 영역 픽셀 비교, 연결 성분, 여백.
- [원본 배치 기록](result/registration.json): 원본 SHA-256, 몸체 경계, 역할별 고정 배율.

## 제작 및 재현

첨부한 660×660 원본 두 장은 `reference/`에 변경 없이 보관했다. 이번에 첨부한
1024×1024 기본·체포·항복·탈옥 원본 다섯 장도 `pose-reference/`에 변경 없이 보관했다.
ImageGen 스킬의 내장 이미지 도구로 부위 분리용 흑백 마스크를 만들었고,
그 결과는 `reference-masks/`, `pose-reference-masks/`, 정확한 프롬프트는
[reference-prompts.json](reference-prompts.json)과
[pose-reference-prompts.json](pose-reference-prompts.json)에 보관했다.
생성 마스크에는 위치 오차와 팔 포함 오류가 있어 그대로 적용하지 않고, 원본에서
보이는 소매 경계에 곡선을 맞췄다. 최종 머리·목·몸통 RGB는 생성 결과가 아닌
첨부 원본에서만 가져온다. 원본에는 체크무늬 제거/색 보정 처리를 적용하지 않는다.

기본/달리기 팔도 같은 첨부 원본에서 각각 분리한다. 체포/항복 팔과 탈옥
팔·손·열쇠·자물쇠는 이번 `pose-reference/` 원본 픽셀에서 직접 추출한다.
탈옥은 첨부 원본의 어깨 위치를 유지하고 얼굴만 앞 레이어로 보호하여, 팔이 목 아래에서
자연스럽게 시작하도록 했다. 합성은 SkiaSharp 도구에서 결정적으로 수행한다.
이전 [prompts.json](prompts.json)과 `generated/*-body.png`는 이력용이며,
현재 몸체 제작에는 사용하지 않는다.

```sh
dotnet run --project tools/PolRob.CharacterAnimation -- \
  docs/character-animation docs/character-animation/result

env DEVELOPER_DIR=/Library/Developer/CommandLineTools \
  /Library/Developer/CommandLineTools/usr/bin/swift \
  -target arm64-apple-macosx15.0 \
  -sdk /Library/Developer/CommandLineTools/SDKs/MacOSX.sdk \
  tools/PolRob.CharacterAnimation/make-preview.swift \
  docs/character-animation/result docs/character-animation/animation.gif
```

결과의 `char_*.png` 21개만 앱 `Resources/Raw/`의 같은 이름으로 복사한다.
`source/`는 재현과 복구용 원본이며 덮어쓰지 않는다. 이전 외곽 정리 도구는
627px 원본 전용이므로 새 1088px 프레임에 적용하지 않는다.

## 검증

- 21개 모두 1088×1088이며, 옆구리 복원 구간을 제외한 원본 머리·눈·목·몸통의
  보호 영역 RGBA 차이 0픽셀.
- 기본·달리기·항복은 역할별로 같은 고정 몸체와 (544, 544) 중심점을 사용한다.
- 체포는 원본 머리·목 보호 영역, 탈옥은 원본 얼굴 보호 영역을 비교했다.
- 비교 마스크도 `result/*-identity-mask.png`, `result/*-protected-head-mask.png`로
  저장해 검사 범위를 확인할 수 있다. 체포 얼굴, 탈옥 얼굴, 도둑 머리띠의 별도
  마스크도 각각 저장하며, 보호 영역 밖의 팔 경계는 시각 검사 대상이다.
- 보이는 영역(알파 32 이상)의 연결 성분은 프레임마다 1개이며, 잘린 동작이나
  떨어진 조각 없이 캔버스 내부 여백을 확보했다.
- 900×600 GIF의 27개 프레임 및 프레임별 시간 정보를 인코딩 후 다시 읽어 확인했다.
- Android 빌드 통과. iOS는 현재 설정된 Xcode 경로가 없어 실행하지 못했다.
  실제 게임의 기기 실행 검증은 수행하지 않았다.

Persistable, 쿼리 성능 최적화                                  GitHub


문제
spring data jpa 사용시, insert, update 작업시 추가로 select 쿼리문이 발생합니다.

발생하는 이유는 jpa repository save 내부 구현에서 persist()가 아닌 merge()가 실행
됩니다.AbstractEntityInformation.isNew()를 통해 확인하는 내부 로직에서 PK가
nullable 하다는 다소 애매모호한 조건 검사도 함께 진행됩니다.




해결
모든 엔티티가 상속받는 BasePkEntity 클래스를 생성했으며 해당 베이스 엔티티는
Persistable이라는 인터페이스를 상속합니다. pk의 타입은 UUID이며 isNew()함수를
재정의 하여 엔티티의 생성 여부를 판별합니다. +추가적으로 hibernate proxy 객체일때
의 엔티티의 동등성 검사를 위하여 equals를 오버라이드 했습니다. 이후 추가 select 쿼
리는 발생하지 않았습니다.
